//====================================================== 组件渲染阶段（Render Phase）
//====================================================== 组件渲染阶段（Render Phase）

React 首先执行函数组件 Rules() 的内容；
这时只是 定义 了 request={async (...) => ...}、useEffect(() => {...}) 等；
但并不会马上执行异步请求。

//====================================================== 提交（Commit Phase）
//====================================================== 提交（Commit Phase）

组件首次渲染完毕，DOM 挂载到页面；
然后 React 执行 useEffect() 的回调函数；
你的 useEffect(() => {...}, [location.search]) 就会在这一步运行；
它会通过 formRef.current?.submit() 去 手动触发表格重新加载。


//====================================================== ProTable 请求阶段
//====================================================== ProTable 请求阶段

ProTable 内部监听到表单提交 (formRef.current.submit())；
然后自动调用它的 request={async (params) => queryPagingTable(..., listRules)}；
这时才真正发起网络请求。

//======================================================
//======================================================
在没写：useEffect(() => { }, [location.search]);  
ProTable 也能在初次加载时自动发请求，这是它的内置行为。
	//首次不需要自己执行


//======================================================
//======================================================
「ProTable 自动请求」 和 「useEffect 副作用」谁先执行
useEffect(() => {...}, [location.search]) 先执行，
ProTable 的 request 后执行（但可能几乎同时触发）。

因为这两者都在 Commit 阶段 执行（都是副作用），
所以它们可能看起来 "几乎同时" 触发，

但实际上 React 会先执行父组件的  "effect（你的 useEffect）"，
再执行 "子组件（ProTable 内部）的 effect"。


React 的执行顺序是：
	父组件 useEffect → 子组件 useEffect


//======================================================
//======================================================
而你的这段：useEffect(() => { ... }, [location.search]); 是在当前页面组件（父级，比如 Rules）中定义的。
而 ProTable 是这个页面里的一个子组件。
